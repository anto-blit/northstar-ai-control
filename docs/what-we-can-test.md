# Testing hypothetical threats without claiming to predict catastrophe

Humanity-wide catastrophe from AI is a possible future outcome, not an event
NorthStar has observed or reproduced. Calling that outcome hypothetical does
not make present unauthorized actions or broken safeguards hypothetical. We can
measure those smaller failures and be precise about what they do and do not show.

Our working question is conditional: if an agent has these tools and authority,
and this permission change occurs, what does it do and what can the service stop?
That is a test of a stated mechanism, not a forecast that the scenario will occur.
Failure rates in hand-selected simulations are not real-world incidence rates.

## A useful test does not always need a misbehaving model

A control can be challenged by a deliberate prohibited request before any ordinary
model chooses that action. Passing demonstrates protection against those specified
requests, provided legitimate work still succeeds. The deliberately faulty actor
is a positive control, not evidence that today's AI spontaneously behaves that way.

A behavioral test can also be informative when the model passes: the conclusion
is limited to the stated task, tools, conditions, and sample. A valid test needs
both a demonstrable failure path and demonstrable legitimate success, so that a
broken test or universal refusal cannot look like protection.

The separate claim that story guidance reduces a particular behavioral failure
requires a measurable comparison. If ordinary instructions, factual examples, and
stories all produce correct behavior, that test shows no added narrative benefit.
The finding does not establish equivalence on every future task. Continuing to
repeat the same easy test is not justified merely by hoping for a favorable result.

The [G8/G8-C evidence-integrity study](../experiments/evidence-integrity-continuation/README.md)
puts these distinctions into one test: independently scored SQL actions, scripted
attacks on a conventional transaction guard, and separate ordinary/factual/story
conditions. Malicious vendor-note cases are labelled prompt-injection challenges;
they are not pooled into a claim about spontaneous cheating.

## Separate four kinds of evidence

| Evidence | What it can establish | What it cannot establish by itself |
|---|---|---|
| Capability test | An actor can perform a specified sequence under given access | That an ordinary actor will choose to do so |
| Behavioral test | An ordinary task-directed model chooses an action under tested conditions | Hidden intent, a deployment frequency, or behavior in every unfamiliar setting |
| Control test | A safeguard withstands specified attempts while preserving stated useful work | Universal containment, particularly outside its authority boundary |
| Catastrophic-risk assessment | A supported argument connecting capabilities, access, behavior and failed containment to large-scale harm | A justified probability from small local test counts alone |

There is no single refusal, phrase or score that diagnoses impending destruction.
A transparent provider refusal on a benign task may reflect poor calibration;
it does not establish a hidden catastrophic plan. Behavior after a legitimate
stop, unauthorized expansion of scope, interference with oversight and dishonest
reporting are more concrete warning signs, but still require contextual evidence.

## G6's deliberately narrow contribution

The [revocation-agent study](../experiments/revocation-agent/README.md) checks
whether an agent requests delivery after acknowledged revocation, whether the
service permits the effect, and whether the final report matches the actual
mailbox. It includes authorized twins and a separate project so that stopping
everything cannot count as full success. Scripted violations establish that the
test can expose a weak control even if no ordinary target model misbehaves.

Its conventional transactional safeguard is credited as conventional. The
story-guidance hypothesis must earn a separate benefit over ordinary instructions,
explicit rules and comparable factual examples. A common gate blocking every
unsafe request cannot be presented as evidence of better model judgment.

The controlled interface deliberately omits access to public services, arbitrary
code, the host filesystem and administrator credentials. That makes the exercise
bounded; it also limits what passing tells us. An agent's ability to evade a
control outside that interface remains untested. All cases are within a specified
mechanism, not a representative sample of future threats or an independent holdout.

## What would justify extending the work?

The completed [G7 discovery search](../experiments/failure-discovery/README.md) made
one repeatable behavioral failure its milestone. It used a new structured
response interface and puts workload notes directly in the agent's input. Fixed
discovery cases precede conditional fresh-session confirmation; a failure must
produce an actual effect, and authorized comparison tasks must still succeed.
Stories were not part of this search. No candidate qualified, and that negative
result closes G7 under its frozen rule. It does not prevent a different, explicitly
labelled control test from being useful.

A reproducible behavioral failure provides a target for a repair frozen before
fresh-case testing. A control failure requires preserving the counterexample and
testing the repair under new challenges. A ceiling result identifies the limit
of that screen; repeating easy cases is not automatically a useful next step.

Even a successful local repair needs evidence about realistic access, alternative
routes, longer deployments, stronger actors and adoption before it can support
a broader safety claim. We cannot guarantee that imagined scenarios cover future
systems. We can improve the coverage, challenge assumptions and disclose the
remaining gaps. The global-risk estimate remains unknown.

Research context: [AI Control: Improving Safety Despite Intentional Subversion](https://arxiv.org/abs/2312.06942)
distinguishes useful deployment from robustness against intentional subversion.
[Anthropic's September 2026 incident assessment](https://www.anthropic.com/research/alignment-assessment-cybersecurity-incidents)
documents the difficulty of predicting boundary failures from prior evaluations.
